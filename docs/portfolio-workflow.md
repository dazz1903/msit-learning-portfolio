# Portfolio Workflow

## Add a complete, evidence-backed entry

1. Choose actual work and review its sharing restrictions using the [publishing guide](publishing-guide.md).
2. Copy the appropriate [project](../projects/PROJECT-TEMPLATE.md) or [assessment](../assessments/ASSESSMENT-TEMPLATE.md) template into a descriptively named folder.
3. State the problem, your contribution, decisions, verification, and limitations. Replace placeholders with verified details.
4. Add only approved evidence, register it in the [evidence index](../evidence/README.md), and link it to the entry.
5. If a genuine evaluation is supplied, create its [feedback record](../instructor-feedback/evaluations/EVALUATION-TEMPLATE.md) and document your response.
6. Update the relevant index. Feature the strongest complete case studies in the main README.
7. Propose the change in a pull request and inspect the full diff before merging.

## First content to collect privately

For the first Codio evaluation, collect the assessment title, subject, evaluation date, exact result and scale, original instructor comments, and a brief explanation of your own work. Check permission and redact private details before placing any version in GitHub.

Until this evidence is supplied, keep results and comments as explicit placeholders. Do not reuse illustrative grades from earlier discussions.

## Quality bar

A recruiter should be able to identify what you built, what you personally contributed, why a decision mattered, and how the result was checked. Favor a few complete case studies over many empty entries. Add prerequisites and reproducible commands when code is public; describe limitations when it is not.
